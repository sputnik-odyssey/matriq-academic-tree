# MatriQ Academic Tree

探索量子物理研究者之间的科研与职业关联。支持中英文姓名、机构和论文搜索，人物名录、机构筛选、一至三度图谱展开、最短关系路径、SVG 导出和来源记录查看。

在线访问：[MatriQ Academic Tree](https://sputnik-odyssey.github.io/matriq-academic-tree/)

## 界面和指导关系类型

网站的整体背景、蓝灰配色与 Times New Roman 衬线字体延续 MatriQ Atom Lab。导入窗口使用更深的文字、更清晰的边框和 12–14px 的核对文字；待选择作者以高对比度底色及文字提示标记。较浅的背景仅用于层级视图和网络视图的图谱画布。

**指导关系类型按用户对工作簿列的定义显示**：`Research Line`（N 列）中引用的人物是该行人物的 PhD 导师，使用红色实线；`Industry Line`（O 列）中引用的人物是该行人物的 Postdoc 导师，使用橙色虚线。箭头均由所引用的导师指向该行学生或受指导者。两种关系都带有阶段标签，使关系类型不依赖颜色也能辨认。同一人物可以分别连接 PhD 与 Postdoc 关系，每条边按自己的来源列显示。

人物边框保持中性，当前选中人物可用黑框或选中标记强调。N / O 列中的全部有效人物关联均按上述规则着色，不以是否有外部核验记录作为显示条件。其他未提供指导阶段的关联保持灰色；学历、职位或图中位置不会改变来源列定义的指导阶段。

图谱中的 PhD / Postdoc 数量统计当前显示的相应指导连线。这些阶段来自用户和工作簿的定义，不代表网站已逐条外部核实其真实性。

`mentorships.json` 中的公开引用仅作补充资料，须对应准确的原有边和人物编号，并保留公开来源 URL 及查阅日期。引用不会覆盖 N / O 列定义的指导阶段，也不是连线着色的前提。共同指导关系可能只包含原表已记录的一位导师，并不表示完整导师名单。上传文件中的“已核实”标记不会自动获得外部核验认证。

## 人物履历

人物卡片和档案显示机构、机构类型及职业身份。来源明确写作 PhD Student 和 PhD Candidate 时分别展示，不把普通博士生自动升为候选人，也不因某人有博士学历就认定仍在读。

在读博士生和候选人优先使用明确提供的预计毕业日期。若只有博士记录的起止年份，则将结束年份标为来自该记录的预计时间，并保留来源说明。日期缺失时显示未提供；已过期的预计日期提示需要更新，不自动改成已毕业。原始博士教育记录仍可查看。

Faculty 显示所在机构及 Faculty，明确的教授职级可作为职位保留。进入公司的人员显示公司及来源实际提供的职位；职位缺失时显示未提供。招聘目标岗位、内部评估及跟进字段不会充当真实职位。

## 添加论文与共同作者关系

点击网站的 **＋论文** 入口，粘贴论文标题、DOI 或 arXiv 编号／链接。标题检索并行查询公开的 Crossref 和 DataCite 元数据；DOI 查询对应记录，arXiv 编号通过其 DataCite DOI 查询。查询无需 API 密钥，但论文是否收录及作者信息完整性取决于这些服务；网络或服务不可用时，网站会提示重试或补充更完整的标识符。

先核对候选论文的标题、年份和作者列表，再检查每位作者对应的人物档案。可以将作者合并到已有档案，或新建独立人物；同名候选存在歧义时需要选择，不把姓名相同直接当作身份相同。ORCID 仅接受规范标识及 `orcid.org` 的有效链接。

作者列表上方显示已选择及待选择人数。未选择的作者行和下拉框以高对比度提示突出显示，窗口底部列出待选择姓名，并提供 **定位下一位待选择作者**。可勾选 **只看待选择作者** 缩短长列表；所有作者均选择已有档案或新建人物后，下一步按钮才可用。

作者匹配支持中间名缩写和首字母变体，例如 `Mikhail D. Lukin` 与 `Mikhail Lukin` 会列为姓名变体候选。变体只提供候选，不自动合并；需选择已有档案或明确新建。已有 ORCID 一致或已确认别名可复用；ORCID 冲突的档案不允许合并。匹配列表下的 **搜索其他已有档案** 可按姓名、机构或档案编号检索完整人物库，并手动选择。

确认合并后，已有主姓名保持不变，论文原始署名保存为别名；若原档案无 ORCID，且本次核对的 ORCID 无冲突，则一并保存。下一篇论文可复用已确认的别名及标识，避免重复新建。确认窗口会显示“论文署名 → 已有人物”的对应关系，人物详情也显示别名。别名与标识保留在本地数据库、公开 JSON、后续表格合并及共享发布中；共享发布仍会复核最新版本的身份信息。

核对后点击窗口底部固定的 **下一步：确认导入**，查看新增人物和合作关系的合并预览。论文的共同作者两两连接，显示为**青色无向合作线**。例如示例论文 *Hardware-Aware Compilation and Execution of Bivariate Bicycle Codes on Neutral-Atom Systems* 有 Jason Ludmir、Aditya Ranjan、Nicholas S. DiBrita、Jason Han、Tirthak Patel 五位作者；若核对为五位不同人物，会产生十组共同作者关系。同一对作者共同署名多篇论文时，只保留一条合作边，并在边中累计论文来源；重复导入同一论文不会重复增加合作边。

点击合作连线可查看对应论文、完整作者列表及 DOI、arXiv 或元数据来源链接，人物档案中也会列出相关论文。共同署名不表示师生关系：既有 N 列 PhD 红色实线、O 列 Postdoc 橙色虚线仍独立保留，不被合作线覆盖。论文所列机构作为发表时的来源信息保存，不自动替代人物的当前机构、职位或职业身份。

### Google Scholar 链接的范围

已核验目录中的引文链接可自动解析，包括示例按钮所用的 `citation_for_view=rPCT_loAAAAJ:eQOLeE2rZwMC`。此示例的题目和五位作者已通过 arXiv 原始记录及 DataCite 交叉确认；不是通用抓取 Scholar 页面。

未知的 Google Scholar 引文 URL 是不可直接解码的标识，静态 GitHub Pages 还受到跨域和反自动抓取限制。此时请在补充标题栏粘贴论文标题，或粘贴包含标题的页面文字作为检索线索，再核对公开元数据返回的候选。不能保证所有 Scholar 链接都能单独自动解析；此入口也不抽取 PDF 原文。

### 预览、下载与共享发布

论文和作者核对后进入 **确认导入** 窗口。点击底部 **确认导入并查看图谱**，即可保存到当前浏览器并直接显示更新后的图谱；刷新后仍保留。图谱上方会显示本地更新提示及 **发布本地更新到共享数据库** 入口。

也可直接点击确认窗口底部 **发布到共享数据库**，展开所有者认证及最终发布确认，按[共享发布流程](#发布到共享数据库)发布。确认按钮固定在窗口底部，作者列表和预览内容单独滚动。支持返回作者核对，并保留已选的匹配档案。仍可下载处理后的公开 JSON。下载数据包含已核对的论文、作者匹配和合作关系，不包含原始上传文件或凭据。保存本地版本不改变其他访客看到的网站。

发布前仍会重新读取 GitHub 的最新共享数据库并重新合并待处理更新；若共享版本变化，需要复核刷新后的预览及作者身份后再发布。后续合并 CSV、XLSX 或 JSON 人物数据时，已保存的论文及共同作者关系会保留。恢复共享版本会撤销尚未发布的本地论文导入。

## LinkedIn 博士与博后履历

点击 **＋ LinkedIn**，或人物档案内的 **导入 LinkedIn 履历**。输入人物的 `/in/…` 链接和 [Apify API Token](https://console.apify.com/settings/integrations)，即可调用 [HarvestAPI LinkedIn Profile Scraper](https://apify.com/harvestapi/linkedin-profile-scraper)。首次使用需在 Apify 账户中启用该 Actor；受限令牌需 Actor Run 权限及读取该任务默认存储的权限。每次仅查询一位人物，设置每任务 US$0.10 的费用上限，实际计费及可用额度以 Apify 为准。

服务接口使用已验证的 `0.0.141` 构建，输入模式为不补充邮箱的 Profile details no email。网站直接从浏览器调用 Apify；Token 仅位于当前窗口内存和对 `api.apify.com` 的 Authorization 请求头中，关闭即清空，不写入 URL、浏览器数据库、GitHub 或履历记录。LinkedIn 登录凭据和 Cookie 不需要提供。第三方服务对提交的链接和任务数据按其自身政策处理。

识别范围为 Education 中明确的博士学位，以及 Education 或 Experience 中明确的 Postdoc 职位，保留机构、学位／职称、开始和结束日期。支持多段博后；日期只有年份时不补造月份；未提供的日期保持为空；Present 标为至今，未来结束时间标为预计，不据日期范围认定已授予学位。抓取结果可在确认前逐条修改、取消或补充。已有 LinkedIn 链接作为身份匹配线索，同名人物需手动核对。若原库中多个档案共用同一 LinkedIn 链接，需明确选择要补充的档案。

点击 **下一步：确认导入** 后，沿用本地确认、公开 JSON 下载及所有者共享发布流程。博士与博后时间线显示在人物详情中，并在后续论文或表格导入、导出及共享发布中保留。履历数据不自动覆盖当前机构和职位，也不会因读过某校就生成导师连线。

API 任务创建后，超时或停止等待不会自动再发起计费任务。可点击 **继续读取本次任务**；若首次创建响应丢失，先在 Apify 控制台查找 Run ID，在“继续已有 Apify 任务”中填入后读取。只有明确点击 **创建新的抓取任务** 并再次抓取才新建任务。抓取只覆盖服务能获取的公开履历，缺失信息不代表该经历不存在。备用入口支持粘贴 Education / Experience 文字，在本地提取并核对，不调用计费 API。

## 上传与更新数据

支持以下结构化文件，单次上传最大 20 MB：

- `.xlsx`：须包含名为 `Mapping` 或 `Mapping Sheet` 的工作表。
- UTF-8 `.csv` 或 `.tsv`：首部包含有名称的字段行。
- `.json`：人物行数组、包含 `rows` 的对象，或网站图谱导出。

暂不支持 PDF、Word、旧版 `.xls` 或任意简历的自动抽取。Excel 公式只读取文件中已保存的值，不执行公式。

原有字段可继续使用 Legal Name、中文名、PhD、CurrentAffiliation、AffiliationType、Research Line、Industry Line 等表头。新增的公开职业字段为：

| 字段 | 用途 |
| --- | --- |
| `Affiliation Type` / `affiliationType` | University、Research institute、Company 等机构类型 |
| `Academic Status` / `academicStatus` | 明确的 PhD Student、PhD Candidate、Faculty、Postdoc 或 Industry 身份 |
| `Job Title` / `jobTitle` | 真实任职职位 |
| `Expected Graduation` / `expectedGraduation` | 四位年份、ISO 日期或明确提供的毕业学期 |

原表的连写表头 `AffiliationType` 保留其旧含义，用于原有身份或角色字段；带空格的 `Affiliation Type` 用于新的机构类型。

新上传的 Excel、CSV / TSV 和 JSON 均使用同一关系规则：`Research Line` / N 为 PhD 导师，`Industry Line` / O 为 Postdoc 导师，引用人物 → 该行人物。JSON 图谱中的关系也沿用其对应的来源列或指导阶段。预览、浏览器本地版本和发布后的共享版本保持这一解释，不等待外部引用补齐后才着色。

上传文件先在浏览器中解析，按公开字段白名单过滤，再预览新增、更新、关联变化与可能的身份歧义。合并会保留原有人物和关联，只用非空的公开字段更新已匹配档案。文件名或行号不能单独确定人物身份，不能充分确认的记录会分开保留。

确认后可将处理后的数据保存到当前浏览器的 IndexedDB。这个本地版本刷新后仍可使用，但不会改变其他访客看到的共享网站；原始工作簿、排除的私有字段和 GitHub 凭据不会写入本地数据库。需要恢复共享版本时，可清除本地导入。

### 发布到共享数据库

只有 GitHub 账号 `sputnik-odyssey` 可以在网站中发布共享更新。发布时使用仅授权本仓库的 fine-grained personal access token，所需仓库权限为 **Contents: Read and write**。令牌仅在当前操作的内存中使用，不保存到 IndexedDB、localStorage、仓库或 URL；不要把令牌写入上传文件。

发布前会重新读取 GitHub 上的最新共享数据库，并据此重新生成合并和变更预览。若共享数据已有变化，需要复核新的预览后再确认发布，避免旧的本地版本覆盖他人的更新。确认后仅提交处理过的公开数据到 `main` 分支的 `data.json.gz`，原始上传文件不会提交。GitHub Pages 随后自动构建，完成后所有访客都能读取更新。

## 公开数据范围

`data.json.gz` 是 gzip 压缩的 JSON 数据，保留人物姓名、专业教育与机构信息、学术主页和公开身份链接、论文记录，以及关系原文与来源行号。网站在浏览器中解压，需要支持 `DecompressionStream` 的现代浏览器；发布压缩更新还需支持 `CompressionStream`。服务器若已自动解压，网站也可直接读取返回的 JSON。

公开版本不包含联系状态、招聘评估、跟进进展、内部备注或原始工作簿。只在关系字段出现的对象以虚线边框标记；无法充分确认的同名人物分别保留档案。机构名称沿用来源写法，不同别名可能分别统计。履历和关系尚未逐条外部核实；PhD / Postdoc 连线按用户定义的来源列解释，部分关系另附公开引用。

## GitHub Pages 和本地预览

发布文件均位于仓库根目录，无需安装依赖或后端。在 **Settings → Pages** 中选择 **Deploy from a branch**，分支为 **main**，目录为 **/ (root)**。

本地运行 `python3 -m http.server 8765 --bind 127.0.0.1`，然后打开 `http://127.0.0.1:8765/`。

完成标题匹配并预览确认后，用户提供的 Scholar 引文链接会随论文来源一起保存。之后再次输入已导入的同一引文标识，可直接定位该论文；共享发布后，其他访客也可使用这条已收录映射。

## 贡献与更正

欢迎通过 Issue 或 Pull Request 更正姓名、机构、学位、实际职位或关系。请提供可公开访问的机构主页、学位论文或论文等证据，并尽量注明档案编号和来源行号。请勿提交私人联系方式、招聘记录或未经证实的个人评价。

`app.js` 负责页面交互，`people.mjs` 整理人物显示信息，`importer.mjs` 解析并合并公开数据，`data-manager.mjs` 和 `import-queue.mjs` 管理预览及待合并更新，`data-sync.mjs` 处理浏览器存储和经所有者认证的发布。`mentorship.mjs` 应用来源列的指导阶段规则并关联补充引用，`graph-render.mjs` 生成带关系类型颜色、实线或虚线、阶段标签和箭头的 SVG。

`paper-manager.mjs` 管理论文检索及作者核对界面；`paper-resolver.mjs` 规范化输入并查询 Crossref／DataCite，`paper-catalog.json` 保存少量经一手来源核验的示例及已知引文标识；`paper-importer.mjs` 处理作者身份匹配、论文合并和可追溯的共同作者关系。它们沿用现有的本地保存、公开 JSON 下载及所有者发布流程。
